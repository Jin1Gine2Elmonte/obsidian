# Knowledge Operating Model

## Purpose
The vault is not merely a backup. It is an external cognitive substrate intended to preserve continuity, reduce repeated explanation, and make large creative and technical systems legible to future AI sessions.

## Three modes

### Preservation
Capture what already exists without reinterpretation.

### Synthesis
Connect multiple records into a higher-level model that reveals structure, patterns, or causal relationships.

### Evolution
When a new conversation changes a project, update the affected canonical nodes while preserving the previous state historically.

## Memory transaction
Every meaningful update should be thought of as a transaction:

**Input -> interpretation -> affected entities -> state change -> consequences -> provenance -> unresolved residue.**

## State types
- `new`
- `active`
- `changed`
- `superseded`
- `paused`
- `abandoned`
- `unknown`

## Information value
Prioritize records that affect:
- long-term identity
- project direction
- canonical world rules
- character continuity
- technical architecture
- major decisions
- unresolved high-impact questions
- repeated patterns

Avoid polluting durable memory with low-value conversational noise unless it explains a meaningful change.

## Retrieval strategy
When an AI receives a task, it should first identify the task's project and anchors, retrieve only the relevant subgraph, then expand outward until enough context exists to answer reliably.

## Compression
Compression is allowed only when semantic relationships and decision-relevant details survive. Shorter is not automatically better.

## Growth control
As the vault grows:
- split overloaded files
- create canonical entity notes
- link instead of duplicate
- keep indexes shallow
- preserve source evidence
- archive obsolete material
- periodically detect contradictions and orphan notes
