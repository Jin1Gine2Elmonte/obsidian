# Persistent Memory — Creative & Project Context

## 1. Collaboration model

The user prefers collaboration that begins with structure rather than surface wording. Before producing an answer or artifact, determine the underlying purpose, emotional effect, center of gravity, internal architecture, mechanisms, relationships, causality, and constraints. Then model the external perspective: how the result looks, feels, reads, and functions to an observer.

Use multiple perspectives when useful: creator, expert/critic, and first-time observer. Keep creative generation and critical evaluation distinct. Treat recurring high-impact concepts as anchor nodes with their own structured subcontexts while preserving their relationships to the larger system.

Expertise should be treated as emergent from repeated experience and stable patterns. Prefer increasingly simple, general principles with strong explanatory power.

The user values direct execution over generic tutorials when the operation can actually be performed. They dislike unnecessary complexity, unnecessary English terminology, and explanations that merely repeat obvious points. Preserve existing constraints and work. Do not invent unavailable facts.

## 2. Writing identity

Preferred writing is dark, gothic, philosophical, psychologically intense, mysterious, violent when narratively justified, and morally gray. Meaning should emerge through scenes, behavior, silence, contradictions, reactions, and emotional pressure rather than direct moral statements.

The user writes from the inside outward and wants mythology to arise from internal imagination rather than being assembled from cultural templates. They seek an original artistic voice and dislike derivative or generic AI aesthetics.

The user enjoys anime/manhwa-scale dramatic intensity and has referenced Solo Leveling and Attack on Titan as inspiration points, but does not want the resulting work to feel obviously Arabic or derivative.

A known writing weakness is that mystery and depth can become stronger than clarity and pacing. When revising, do not automatically add more mystery; inspect whether the real problem is progression, causal logic, scene purpose, clarity, rhythm, or emotional movement.

A philosophical foundation: absolute nothingness cannot literally manifest as an entity because manifestation would make it existent. This distinction is central to the work The Last Thing to Be Forgotten.

## 6. AI memory / Obsidian architecture

A major long-term goal is an external memory system that survives model changes and can be shared among AI systems such as ChatGPT and Gemini.

Obsidian is intended as a portable Markdown knowledge substrate rather than merely a note-taking application. The desired architecture includes:
- conversations
- messages
- synchronization state
- semantic search
- text search
- provenance
- metadata
- topics
- projects
- characters
- technologies
- dates
- importance
- relationships

Possible bridges investigated include Obsidian Local REST API, Obsidian MCP servers, semantic-vault-style tooling, synchronization layers, and Android-based automation. A bridge/API/MCP layer is required for an AI to access the vault automatically.

The user strongly prefers the simplest architecture that actually works and wants to avoid unnecessary storage layers, unnecessary terminal/Termux use, or infrastructure that adds complexity without real benefit.

The user has also explored converting conversations to text so multiple AI systems can share context, and an Android accessibility-service or IME approach for injecting context into AI applications.

## 12. Cross-project principles

1. Preserve relationships, not only isolated facts.
2. Distinguish canon from speculation.
3. Distinguish current decisions from abandoned experiments.
4. Preserve historical evolution where it matters.
5. Do not invent missing history.
6. When a concept becomes important enough, promote it to an anchor node.
7. Treat every project as part of an integrated creative/technical ecosystem when the relationship is real.
8. Favor direct, concrete execution.
9. Preserve user constraints exactly.
