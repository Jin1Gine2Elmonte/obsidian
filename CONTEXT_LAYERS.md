# Context Layers

The archive should preserve different depths of context instead of compressing everything into one summary.

## Layer 0 — Identity of the work
The few principles that should survive almost any compression: creative direction, reasoning architecture, major project anchors, and current strategic goals.

## Layer 1 — Durable memory
Stable preferences, recurring projects, canonical characters, major technical architecture, important decisions, and established world rules.

## Layer 2 — Episodic memory
Important conversations, breakthroughs, corrections, failed approaches, and turning points. These preserve the history of how an idea became what it is.

## Layer 3 — Semantic memory
Definitions, relationships, conceptual structures, taxonomies, causal models, and cross-project patterns.

## Layer 4 — Operational memory
How to actually perform a workflow: tools, files, deployment patterns, integration methods, prompts, schemas, and troubleshooting lessons.

## Layer 5 — Raw evidence
User-supplied source text, exported conversations, repository files, screenshots, links, and other material that supports higher-level notes.

## Compression rule
Higher layers may summarize lower layers, but summaries must never pretend to be the original evidence. When detail is important, link back to the deeper layer.

## Retrieval rule
For a new task, retrieve from broad to narrow:
1. Identity / purpose.
2. Relevant project.
3. Relevant anchors and relationships.
4. Historical decisions.
5. Operational detail.
6. Raw evidence when precision requires it.

This allows the system to remain both fast and deep.
