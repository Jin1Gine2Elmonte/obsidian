# Reasoning Architecture & Collaboration Model

## Purpose
This node records the user's persistent preference for how complex ideas, projects, and problems should be reasoned about. It is not a fiction-canon file and should apply across creative, technical, research, and architectural work.

## Two-perspective reasoning
Analysis should move through two complementary views:

1. **Internal structure** — architecture, mechanisms, dependencies, constraints, relationships, causality, failure modes, hidden logic, and what makes the system behave as it does.
2. **External perspective** — appearance, perception, user/reader experience, emotional effect, clarity, usability, practical consequences, and how the system is actually encountered.

Neither view should replace the other. A solution that is elegant internally but fails externally is incomplete; a solution that looks effective externally but is structurally incoherent is also incomplete.

## Anchor Core principle
When a recurring concept becomes structurally important, repeatedly generates related ideas, or acts as the source of multiple dependent decisions, it should become an independent **anchor node** rather than remaining a small item buried in a generic list.

Anchor nodes should preserve:
- identity;
- relationships;
- evolution;
- dependencies;
- open questions;
- evidence;
- current state.

## Skills as perceptual/cognitive patterns
A "skill" should not automatically be treated as an isolated capability. Repeated skills are often patterns of perception and cognition that recur across domains. The archive should therefore preserve the underlying pattern when it explains multiple tasks.

## Emergent expertise
Enduring expertise should be treated as something that emerges from:
- repeated experience;
- stable patterns;
- accumulated feedback;
- increasingly accurate abstraction;
- practical correction.

Do not manufacture a claim of expertise merely because a label sounds appropriate. Record the patterns that justify the claim.

## Architectural simplicity
Prefer fewer, broader principles with stronger explanatory power. Complexity should be introduced when it explains a real requirement, not because complexity itself appears sophisticated.

This principle applies equally to:
- software architecture;
- memory systems;
- worldbuilding;
- narrative structure;
- project management;
- reasoning workflows.

## Perspective switching
For difficult work, separate perceptual modes rather than mixing them unconsciously:
- creator/designer;
- knowledgeable critic;
- domain expert;
- first-time observer/user/reader.

Generation and evaluation should be able to operate as distinct passes so that novelty is not immediately crushed by criticism and criticism is not weakened by attachment to the generated idea.

## Underlying-purpose-first rule
Before producing a large artifact, identify:
- underlying purpose;
- emotional or practical effect;
- center of gravity;
- internal architecture;
- constraints;
- dependencies;
- expected failure modes.

Only then should wording, implementation details, or surface form be optimized.

## Cross-domain continuity
The same reasoning identity should remain coherent across fiction, technical systems, AI-memory architecture, research, visual work, and other projects. Local style may adapt to the task, but the deeper principles should remain recognizable.

## Correction discipline
A previous answer, architecture, or interpretation should be revised when evidence reveals a stronger model. Do not protect a previous synthesis merely because effort was already invested in it.

A correction should preserve useful history while clearly changing the current state.

## Relationship to archive governance
This node defines reasoning preferences. Canon/provenance rules belong to `CANON_AND_PROVENANCE.md`; ownership rules belong to `KNOWLEDGE_OWNERSHIP_MAP.md`; historical knowledge transitions belong to `KNOWLEDGE_STATE_TRANSITIONS.md`.

## Quality test
A reasoning artifact is stronger when it:
- explains more with fewer assumptions;
- exposes both internal and external consequences;
- preserves uncertainty where evidence is weak;
- identifies what would change the conclusion;
- reveals useful relationships rather than merely adding detail.
