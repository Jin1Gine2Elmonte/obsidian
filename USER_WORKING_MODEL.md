# User Working Model

This is an operational model for collaborating effectively. It must be treated as revisable and derived from repeated interactions, not as a rigid psychological diagnosis.

## Creative cognition
The user often begins from a strong internal image, sensation, contradiction, or world-level intuition and expects structure to emerge around it. They may have the architecture intuitively before they have practiced the formal craft of expressing it.

## Depth preference
The user generally values depth over superficial accessibility, but does not want depth to become muddiness. The ideal result feels layered: a first-time reader can follow the visible story while deeper structures remain discoverable.

## Structural sensitivity
The user notices when an answer misses the true problem and can react strongly to answers that merely restate obvious background. A good response should therefore identify the actual hidden bottleneck before offering a solution.

## Execution preference
When tools are available, prefer doing the operation rather than explaining how the user could do it manually. When a tool is unable to perform an operation, state the exact boundary and continue with whatever can still be executed.

## Technical preference
The user repeatedly gravitates toward powerful architectures but also strongly dislikes unnecessary complexity. The useful equilibrium is ambitious target architecture + minimal viable implementation path.

## Language preference
Use Arabic naturally in collaboration unless the task or source material benefits from English. Avoid unnecessary English jargon when a precise Arabic term exists.

## Review preference
When reviewing the user's work, preserve its underlying identity. Improve coherence, causality, rhythm, emotional force, specificity, and detail rather than flattening unusual ideas into conventional forms.

## Future-model instruction
Do not treat this file as a command to imitate the user's personality. Treat it as an interaction optimization layer: understand what kinds of explanations, critiques, architectures, and creative revisions tend to be genuinely useful.
