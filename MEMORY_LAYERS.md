# Memory Layers

The archive should be read as a layered memory system rather than a flat biography.

## Layer 0 — Provenance
Every durable statement should ideally retain where it came from: direct user statement, prior project record, inferred pattern, or later interpretation. Never silently upgrade an inference into a fact.

## Layer 1 — Stable identity of work
Creative orientation, collaboration principles, reasoning architecture, recurring aesthetic constraints, and long-lived project goals.

## Layer 2 — Canon
Confirmed facts inside fictional universes, confirmed project architecture, established naming, power-system rules, character histories, and design constraints.

## Layer 3 — Working state
Current drafts, experiments, prototypes, technical implementations, unresolved architecture, and temporary decisions.

## Layer 4 — Historical state
Abandoned approaches, previous versions, renamed projects, failed deployments, earlier architecture decisions, and why they changed.

## Layer 5 — Open loops
Questions, missing facts, contradictions, unresolved story logic, technical blockers, and ideas waiting for testing.

## Layer 6 — Relationships
Connections between projects, people/characters, concepts, technologies, decisions, and historical events.

## Layer 7 — Retrieval summaries
Short high-density summaries designed for an AI to load quickly before opening detailed records.

## Layer 8 — Conversation records
Verbatim transcripts or user-supplied exports when they become available. Summaries must never pretend to be transcripts.

## Layer 9 — Derived cognition
Patterns inferred from repeated dialogue: preferences, recurring failure modes, design instincts, and strategic tendencies. These should always be marked as interpretations rather than hard facts.

## Principle
A future AI should be able to reconstruct not only what exists in the vault, but the state of knowledge, confidence, chronology, and relationships that produced it.
