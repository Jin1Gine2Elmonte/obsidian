# Idea Lineage Recovery — Pass 01

## Purpose
Preserve the evolution of recurring ideas without pretending that approximate memory provides exact dates or source-level chronology.

This record tracks **idea lineage**, not fictional canon and not a verbatim conversation timeline.

## Temporal model
Each lineage entry uses a state sequence rather than an invented date:

`SEED -> FIRST_RECOGNIZED FORM -> REFORMULATION -> BRANCH -> PROJECT/DOMAIN USE -> CURRENT STATUS`

Exact dates remain `UNKNOWN` unless a dated source establishes them.

## Branching rule
When one idea appears in multiple projects or domains, record:
1. recurrence;
2. local meaning;
3. confirmed transition, if any;
4. unresolved ancestry;
5. current form.

Never infer a single origin merely because the vocabulary is similar.

## Recovery targets
For each lineage, the highest-value future evidence is:
- the earliest recoverable message where the concept appears;
- the first explicit reformulation;
- the first project-specific embedding;
- any later message explicitly stating that one form evolved from another;
- any rejection that permanently changed the concept.

## Evidence boundary
This file is derived from accessible memory/context plus existing archive structure. It is not a substitute for original conversation transcripts.
