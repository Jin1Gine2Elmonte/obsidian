# Archive Learning Curve

## Scope
This file records durable lessons about how the archive reconstructs, preserves, and audits knowledge. It is an archive-methodology record, not fictional-world canon and not a replacement for the repository's Git-evolution history.

## Why this exists
This repository has already passed through several stages of memory construction. Preserving that evolution matters because the archive itself is a project with a history.

## Stage 1 — summary accumulation
The first approach emphasized gathering broad facts about the user's writing, projects, characters, technology, and preferences.

### Failure mode
Volume could increase without increasing factual density. Rephrasing the same knowledge created the appearance of progress.

## Stage 2 — structural decomposition
The archive began separating fiction, technology, memory architecture, reasoning preferences, projects, and cosmology.

### Improvement
Relationships became easier to preserve and future retrieval became more targeted.

## Stage 3 — evidence awareness
The archive introduced canon ledgers, conflict logs, scene evidence, provenance states, and version control.

### Improvement
The system became capable of admitting uncertainty instead of silently filling gaps.

## Stage 4 — causal reconstruction
The archive began storing transitions, state machines, relationship dynamics, dependency graphs, and propagation rules.

### Improvement
The world could be represented as changes over time rather than a static encyclopedia.

## Stage 5 — memory-density modeling
Current work recognizes that the accessible memory itself is uneven. Some anchors survived strongly; others survived only as names or broad roles.

### Improvement
The archive now records not just facts, but the **shape and quality of what is remembered**.

## Current governing principle
The next useful unit of progress is not another summary. It is one of:
- a recovered fact;
- a recovered scene;
- a resolved identity;
- a resolved project/version boundary;
- a newly confirmed relationship;
- a historical correction;
- a causal transition;
- a useful negative rule;
- a source that upgrades confidence.

## Anti-regression rule
Future additions should be rejected or merged when they merely restate existing knowledge without changing its structure, confidence, relationship graph, chronology, or explanatory value.

## Ownership boundary
This file owns archive-reconstruction lessons specifically. Repository development history remains owned by `ARCHIVE_EVOLUTION_FROM_GIT.md`; durable decisions and general lessons remain owned by `DECISIONS_AND_LESSONS.md`; fictional-world facts remain owned by their specialized `WORLD/` nodes.
