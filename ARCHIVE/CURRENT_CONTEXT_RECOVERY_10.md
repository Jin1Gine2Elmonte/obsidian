Preserve additional non-canonical context remembered across prior collaboration: interests, research habits, small projects, tool choices, naming practices, reading, and practical workflow details that were not sufficiently represented by the earlier recovery passes.

# I. Research and learning interests

- Recurring interest areas include AI and technology, literature and writing, philosophy and psychology, politics/geopolitics, and the changing capabilities of AI systems.
- Long-form reading is valued over superficial summaries when a subject benefits from sustained argument.
- A recurring preference was for substantial free long-form reading, with an approximate reading window of 25–45 minutes, and for a free-access route when the ideal source is paywalled.
- Research is most useful when it explains not only what happened but why, what alternatives existed, what evidence distinguishes them, and what remains unresolved.
- The user has repeatedly been interested in emerging AI capabilities and the implications for creative work, writing, agents, memory, and personal knowledge systems.

# II. Tool and workflow preferences

- Tools are judged by actual utility and reliability, not by branding or theoretical capability.
- A tool that cannot reliably execute the required operation should not be treated as equivalent to a tool that merely describes the operation.
- The user often chains tools across domains: AI models, GitHub, Obsidian/Markdown, deployment platforms, image generation, audio generation, and web/application tooling.
- The user values portable workflows where the underlying knowledge remains usable if a particular application, provider, model, or gateway changes.
- When a workflow fails, the user tends to investigate the whole stack: model behavior, system instructions, tool availability, proxy/routing, context assembly, deployment/runtime, and external constraints.

# III. Naming and terminology practice

- Names are treated as structural parts of fictional identity rather than interchangeable labels.
- Alias, transliteration, translation, and actual canon name should be distinguishable when provenance matters.
- The same or similar title does not prove that two projects are identical.
- A changed name can represent a rename, a new generation, a branch, or a distinct project; historical evidence must decide which.
- The user has repeatedly explored the nuance between Arabic meaning and a proper-name/transliterated form when naming fictional entities and characters.

# IV. Website / application experimentation

- WordPress and Netlify appeared in website/deployment discussions.
- HTML RPG interfaces and progression-oriented websites were explored as ways to turn fictional systems into interactive experiences.

# V. RPG / interactive-system design

- The user has explored RPG/progression systems inspired by recognizable progression fantasies while wanting an original identity rather than direct imitation.
- Solo Leveling / Nano Machine were referenced as inspiration points for progression-system feel, not as permission to copy their fictional mechanics.
- The recurring goal in these experiments is to combine atmosphere, progression, system clarity, and a strong identity of the fictional world.
- Interactive HTML/RPG ideas should therefore be treated as their own project layer rather than automatically merged with the novel canon.

# VI. Visual and media workflow details

- Image work often uses surgical editing: change one requested property while preserving all approved composition, character, lighting, typography, city/background, and palette elements.
- The user is sensitive to accidental redesign and to outputs that look generically AI-generated.
- Visual quality is judged not only by polish but by continuity of composition, atmosphere, hierarchy, and narrative intent.
- Similar principles apply to music and voice work: the target feeling, location/atmosphere, and relationship meaning can matter more than generic genre labels.

# VII. Model evaluation habits

- The user has explored many model families, including ChatGPT, Gemini, DeepSeek, GLM, Nemotron, and provider SDKs.
- Model evaluation is often behavioral: how well the model preserves context, reasons under constraints, follows tools, maintains identity across turns, and investigates uncertainty.
- When several plausible technical causes exist, the user prefers parallel investigation or multiple independent model perspectives rather than accepting the first plausible diagnosis.
- A shared environment does not guarantee shared behavior; system prompts, tool bindings, routing, proxy code, runtime state, context windows, model configuration, and provider-side behavior may all matter.

# VIII. Memory-system practical goals

- The user wants continuity across models and applications rather than a provider-specific memory silo.
- Obsidian/Markdown is valuable because it is readable and portable.
- MCP, APIs, gateways, accessibility/IME methods, semantic search, and embeddings are treated as mechanisms for access or retrieval, not as the durable source of truth.
- Raw conversation history and distilled memory should remain separate so that compression does not become irreversible loss.
- The desired retrieval behavior is selective: retrieve the smallest context that preserves the needed meaning, prioritizing anchors, relationships, current state, constraints, and relevant historical evidence.

# IX. Creative-production workflow

- The user can generate large conceptual structures intuitively, then wants help translating that intuition into executable prose, scenes, architecture, prompts, or systems.
- The workflow therefore benefits from switching modes: conception, structural analysis, generation, critique, implementation, and verification.
- The user repeatedly values preserving the original purpose and emotional center when translating an abstract idea into a concrete artifact.
- Large outputs should contribute to the larger system rather than behaving as isolated documents.

# X. Cross-domain continuity pattern

Recurring motifs have appeared in different domains, but should remain patterns rather than shared canon unless evidence proves a connection:

- memory / forgetting;
- identity / versions;
- reality / fiction;
- creation / erasure;
- system / individual;
- control / freedom;
- mystery / knowledge;
- immense scale / intimate consequence;
- external access / internal source of truth.

These are useful analytic invariants because they recur across fiction and technical work, but recurrence alone does not establish a direct causal connection between projects.

# XI. Small-detail preservation rule

A small detail should be preserved when it can later:
- distinguish projects;
- identify a version;
- explain a later decision;
- establish a constraint;
- reveal a recurring motif;
- reconnect a fragment to a larger concept;
- prevent a previously rejected interpretation from returning.

Small details should not be promoted to major canon merely because they are memorable.
