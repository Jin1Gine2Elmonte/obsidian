# Fiction Version Control — Jin World

## Problem
The user's creative history spans multiple iterations, projects, and possibly parallel versions of names, characters, and cosmologies. A single flat canon is unsafe.

## Required dimensions
Every major fictional record should carry:
- project name;
- universe/world identifier;
- version/iteration identifier when known;
- development phase;
- first known appearance;
- current status;
- supersedes/superseded-by relationships.

## Why versions matter
A later iteration may intentionally change:
- Jin's identity;
- relationships;
- power limits;
- cosmological hierarchy;
- family history;
- names;
- geography;
- tone;
- plot.

Such changes are evolution, not necessarily contradictions.

## Conflict categories
When two records disagree, classify the conflict as:
1. same canon, unresolved contradiction;
2. later correction;
3. alternate draft;
4. separate project;
5. separate universe;
6. separate character sharing a name;
7. unknown.

## Recovery principle
Do not resolve ambiguity by choosing the most elegant version. Resolve it from chronology and explicit user statements.
