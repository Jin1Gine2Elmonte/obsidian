# Memory → Canon Pipeline

## Purpose
Define how information should move from remembered conversation context into durable fictional canon without collapsing uncertainty or losing historical evolution.

## Layer 0 — Raw source
The original user message, scene, dialogue, image description, code, outline, or correction.

This is the strongest evidence.

## Layer 1 — Local extraction
Extract only what the source explicitly establishes:
- entity;
- event;
- relation;
- rule;
- motive if directly stated;
- chronology;
- project/version;
- explicit correction.

Do not add interpretation here.

## Layer 2 — Structured evidence
Attach:
- source;
- date if available;
- project/world;
- version;
- confidence;
- temporal status;
- supersession;
- affected nodes.

## Layer 3 — Canon node
Promote only stable information into the canonical node. Preserve the exact wording or scene reference for high-impact facts.

## Layer 4 — Derived structure
Create state machines, causal chains, relationship models, institutional implications, and cosmological hypotheses only after separating them from source facts.

## Layer 5 — Synthesis
Produce concise high-level summaries for future AI context. A synthesis must preserve the fact's significance and relationships without pretending to preserve every source detail.

## Layer 6 — Propagation
When a canon node changes:
1. find direct dependencies;
2. find temporal dependencies;
3. find relationship dependencies;
4. find version dependencies;
5. update affected syntheses;
6. preserve the superseded state historically.

## Promotion rule
A statement should move upward only when evidence supports it. A beautiful interpretation is not a stronger source than a plain user sentence.

## Demotion rule
A later direct user correction can demote an earlier canon claim to historical/obsolete status while preserving it as part of the project's development history.

## Special rule for Jin
Because Jin has multiple versions/iterations, no generic statement about Jin should automatically be copied into every variant. Version ownership must be assigned first.

## Special rule for Almont/Ryota/Jin
Because of the current identity ambiguity around the child-history branch, all three names must remain separated until source evidence resolves their relationship.

## Special rule for cosmology
Names such as Existence Sublime, Entity of Forgetting, Primordial Rift, and Shadows of the First Creation must not be placed into a single hierarchy simply because they sound connected. Explicit project/world membership is required.
