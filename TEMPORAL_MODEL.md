# Temporal Model

## Purpose
Keep three different kinds of time separate throughout the archive.

### 1. Conversation time
When the statement or decision was made in an actual conversation/source.

### 2. Project time
Which project generation, rewrite, prototype, or iteration the statement belongs to.

### 3. Fictional/world time
When an event occurs inside the fictional world itself.

## Rule
Never infer one clock from another.

A later conversation can describe an earlier fictional event. A later project generation can deliberately rewrite an earlier version. A repository commit records archive history, not story chronology.

## Required fields for recovered historical material
- source/conversation date when known;
- project/generation when known;
- fictional date/sequence when known;
- temporal confidence;
- whether the entry is historical, current, superseded, or unresolved.

## Jin-specific importance
The Jin/Ryota identity ambiguity cannot be solved merely by ordering summaries. Evidence must establish whether the two histories occur in the same project generation, different generations, or the same fictional timeline.

## Almont branch
The sequence around Arisa's death, escape, return, rebellion, disappearance, and later return should be represented as fictional state transitions only when source evidence establishes their ownership by Jin, Ryota, or another character.

## Preservation rule
When time is unknown, store the uncertainty rather than inventing a date.
